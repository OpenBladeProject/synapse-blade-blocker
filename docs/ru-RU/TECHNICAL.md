# Техническое руководство

[English](../../TECHNICAL.md) | [简体中文](../zh-CN/TECHNICAL.md) | Русский

Порядок работы с окном описан в [README](../../README.ru-RU.md). Приведённые ниже команды позволяют подготовить, применить и отменить патч из PowerShell.

<a id="compatibility-and-status"></a>
## Совместимость и состояние

Чтобы проверить версию инструмента без подключения к Интернету, выполните следующую команду. Для неё не нужны Synapse, Node.js, поиск установленной версии или права администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\BladeBlocker.ps1 -Version
```

Инструмент подготавливает каждую установленную сборку из её собственного исходного архива без списка разрешённых версий Synapse или хешей исполняемого файла. Для каждого структурного изменения должно найтись ровно одно место в коде. Во время подготовки инструмент проверяет синтаксис JavaScript и побайтово сверяет все неизменённые упакованные файлы. При изменённой или неполной структуре подготовка останавливается и создаётся очищенный отчёт для задачи.

Окно остаётся отзывчивым во время проверок и подготовки и объясняет, каких обязательных компонентов или резервных копий не хватает, какие контроллеры работают и как изменилась установленная версия. Если отменить запрос прав администратора, установленный архив не изменится. Операции Apply и Restore не останавливают и не перезапускают приложения. С повышенными правами выполняется только выбранная операция; само окно сохраняет обычные права пользователя.

После обновления Synapse обновите состояние и подготовьте обновлённую сборку. Не используйте старую резервную копию для изменившейся установленной версии. Если операция завершилась ошибкой, разверните раздел **Backups and diagnostics**. Выберите **Copy diagnostic details**, чтобы получить очищенные сведения о состоянии, или **Open saved reports**, чтобы открыть отчёты о совместимости, созданные при подготовке или замене архива. Следуйте показанным инструкциям по восстановлению. Если результат замены нельзя проверить, сохраните резервные копии и не запускайте Synapse, пока установленная версия не будет приведена в согласованное состояние.

Окно проверяет содержимое архива и находит прежние патчи даже без применённого маркера или папки подготовки. Оно сообщает о распознанных патчах, неполных или неизвестных следах блокировщика либо об отсутствии распознанных изменений. Состояние нечитаемых архивов остаётся неизвестным. Совпадения хеша резервной копии показываются отдельно; они не доказывают, что сохранённый оригинал никогда не изменялся. Для Restore всегда требуется соответствующий проверенный оригинал.

<a id="prepare-the-patch"></a>
## Подготовка патча

Откройте PowerShell в распакованной папке. Закройте Synapse и не запускайте его программу обновления во время подготовки и применения патча.

```powershell
npm test
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Prepare.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\BladeBlocker.ps1 -Mode Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\BladeBlocker.ps1 -Mode Apply -WhatIf
```

Для локальной проверки модулей задайте в `BLOCKER_PREPARATION_DIRECTORY` папку, которую вернула команда Prepare, затем выполните `npm run test:local`.

Поиск использует точную папку активного процесса AppEngine, если он доступен, или самую новую папку `app-VERSION` в `%ProgramFiles%\Razer\RazerAppEngine`. Оба скрипта принимают параметр `-InstallDirectory`, позволяющий явно указать папку в пределах этой стандартной структуры. Они отклоняют неоднозначные активные установленные версии и пути установки с точками повторного разбора.

По умолчанию при каждой подготовке создаётся новая папка `<timestamp>-<id>` в **Documents > Synapse Blade Blocker > Backups**. Инструмент использует расположение системной папки Documents, в том числе когда она перенаправлена. В строке **Backups** окна выберите **Open folder**, чтобы открыть эту папку, или **Choose location…**, чтобы сохранять новые резервные копии в другом месте. Предыдущие резервные копии остаются на своих местах. Кнопка **Use Documents default** снова выбирает папку Documents. Блокировщик атомарно сохраняет выбранное и предыдущие расположения в `%LOCALAPPDATA%\SynapseBladeBlocker\settings.json`.

Каждая папка содержит `original.asar`, `blocked.asar`, извлечённые исправленные модули и `preparation.json`. Манифест записывает хеши фактического исходного файла, исполняемого файла и результата, а также встроенные идентификаторы реестра Blade и отпечаток исходного кода патча. Существующие папки подготовки, резервные копии и прежний локальный файл `original.asar` сохраняются. Во время подготовки установленные файлы только читаются.

Автоматический поиск проверяет выбранную папку, ранее выбранные расположения, стандартную папку Documents, прежнюю папку `%LOCALAPPDATA%\SynapseBladeBlocker\Backups` и папку `prepared/` из старых версий пакета. Хеши исполняемого файла и архива установленной версии должны совпасть с папкой подготовки. При выборе между совпадениями инструмент предпочитает неповреждённую резервную копию оригинала. Если папка явно указана через `-PreparationDirectory`, инструмент не переходит к другой резервной копии. Другие старые папки подготовки по-прежнему можно выбрать вручную.

Команда Patch в оконном приложении повторно использует папку подготовки только после проверки по текущему исходному коду патча; иначе она создаёт новую. Перед записью Apply проверяет отпечаток исходного кода патча и детерминированное преобразование проверенного оригинала, поэтому старый или изменённый подготовленный патч нельзя повторно использовать как текущий. Старые оригиналы по-прежнему пригодны для Restore. Apply и Restore получают вычисленный путь папки подготовки явно, в том числе после запроса прав администратора; обязательные проверки целостности исполняемого файла и архива, а также остановленных контроллеров сохраняются.

Apply и Restore находят папку подготовки, хеши архива и исполняемого файла которой соответствуют выбранной установленной версии. Чтобы выбрать её явно, используйте `-PreparationDirectory`. Для локальных тестов модулей `BLOCKER_PREPARATION_DIRECTORY` должен указывать на проверенную папку подготовки, созданную из текущего исходного кода.

Относительные пути в `-InstallDirectory` и `-PreparationDirectory` разрешаются относительно текущей папки PowerShell. Проверки операций во временной среде охватывают Windows PowerShell 5.1 и PowerShell 7, в том числе часовые пояса, отличные от UTC, и проверку маркеров UTC. Маркеры с будущей датой отклоняются. При ранних ошибках поиска версия PowerShell сохраняется в очищенной диагностике; отсутствие подходящей папки подготовки указывается как отсутствие входных данных.

<a id="apply-the-patch"></a>
## Применение патча

Закройте Synapse и завершите работу OpenBlade через страницу Settings. Выполните Apply в окне PowerShell с правами администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\BladeBlocker.ps1 -Mode Apply
```

Убедитесь, что показано `Success: True`, а значение `ToolVersion` соответствует вашему пакету, затем запустите Synapse обычным способом. При успешном выполнении Status, Prepare, Apply и Restore указывают одну версию инструмента из пакета. Вспомогательный процесс проверяет исходный архив для отката, помещает патч во временное расположение, проверяет, не началось ли параллельное обновление, атомарно заменяет `app.asar`, сохраняет уникальную резервную копию установленного файла, проверяет результат и только после этого записывает `resources/synapse-blade-blocker.json`.

Дождитесь полной загрузки Synapse, откройте страницу периферийного устройства и проверьте, что оно работает, а Blade отсутствует. Затем запустите OpenBlade, если вы им пользуетесь. Если вы заметили неожиданное поведение, восстановите исходный архив и сообщите о проблеме, как описано ниже.

<a id="using-openblade"></a>
## Использование OpenBlade

[OpenBlade 0.21.0 или новее](https://github.com/OSSBlade/openblade-core/releases/latest) распознаёт применённый патч, проверяя фактически установленные файлы и перезапуск Synapse после применения. Если патч отсутствует, изменён или устарел, обычные проверки конфликтов сохраняются. Используйте последнюю версию, чтобы получить последующие исправления совместной работы.

После загрузки интерфейса Synapse может запустить свой вспомогательный процесс подсветки Windows `razerwdl`. OpenBlade принимает этот процесс только тогда, когда подтверждены его подлинность и исправленный родительский процесс Synapse, а свежая проверка устройств Windows не обнаружила исключённый интерфейс подсветки Blade. При неизвестной подлинности устройства, ошибке перечисления, независимом вспомогательном процессе или других конкурирующих контроллерах проверки сохраняются. Это не отключает подсветку Windows или функции периферийных устройств.

OpenBlade 0.24.3 также разрешает HyperBoost при наличии проверенного патча блокировщика и известных псевдонимов служб Synapse. Проверенная служба RGS не блокирует HyperBoost; непроверенный процесс с именем RGS или программы обновления по-прежнему блокирует его. Вспомогательный процесс подсветки Windows с подтверждённой подлинностью Razer также не блокирует HyperBoost; остальные проверки контроллеров, проверки точного устройства и требования к питанию продолжают действовать. Полные правила приведены в [руководстве по совместной работе основного приложения](https://github.com/OpenBladeProject/openblade-core/blob/v0.24.3/docs/synapse-blade-blocker.md).

Проверка установленной версии в сентябре 2026 года прошла с Synapse AppEngine 4.0.823 и работающим отложенно запущенным вспомогательным процессом: Pro Click V2 отображалась и работала, а Blade отсутствовал. OpenBlade не показал предупреждений о конфликте. Точные проверенные версии и ограничения приведены в [VALIDATION.md](VALIDATION.md). Сообщайте о результатах с другими конфигурациями.

<a id="restore-the-original"></a>
## Восстановление оригинала

Чтобы отменить изменение, закройте Synapse, завершите работу OpenBlade и выполните в PowerShell с правами администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\BladeBlocker.ps1 -Mode Restore
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\BladeBlocker.ps1 -Mode Status
```

Restore проверяет соответствующий оригинал, восстанавливает его и удаляет маркер применённого патча. Для работы ему не нужен исправленный архив. Повторное выполнение Apply или Restore даёт тот же результат, что и однократное; Apply может заново создать отсутствующие метаданные после проверки уже исправленного архива. Сохраняйте все локальные оригиналы и резервные копии установленной версии. Инструмент сохраняет неизвестные архивы и обновления исполняемого файла, а не перезаписывает их старой сборкой. После обновления подготовьте новую исходную сборку. Для повторного применения патча требуется действие пользователя. Инструмент оставляет управление процессами пользователю и не устанавливает службы или драйверы.

Не запускайте программу обновления во время замены. Последняя проверка хеша обнаруживает уже произошедшие обновления, но не может помешать программе обновления изменить файлы сразу после неё. Если проверка замены завершилась ошибкой, сохраните указанную резервную копию и не запускайте Synapse, пока установленная версия не будет приведена в согласованное состояние.

<a id="if-a-patch-fails"></a>
## Если не удалось применить патч

При ошибках Prepare, Apply и Restore выводится пригодная для копирования диагностика в формате Markdown, которую инструмент также пытается сохранить в игнорируемой папке `diagnostics/`. Она включает версии инструмента и среды выполнения, контракт патча, обнаруженную версию AppEngine, доступные полные хеши, этап и категорию ошибки, а также название и число отсутствующих или неоднозначных опорных элементов, если эти сведения доступны. Необработанные исключения, локальные пути, имена пользователей, серийные номера, содержимое архива и нативный код исключаются. Ошибка сохранения отчёта не скрывает исходную ошибку.

Вставьте отчёт в [задачу о совместимости](https://github.com/OSSBlade/synapse-blade-blocker/issues/new/choose) и опишите, что вы пытались сделать. Не загружайте архивы поставщика или необработанные файлы захвата. Инструмент никогда не отправляет задачу автоматически.

<a id="applied-metadata"></a>
## Метаданные применённого патча

```json
{
  "schemaVersion": 1,
  "patchId": "OSSBlade/synapse-blade-blocker",
  "archiveSha256": "<full installed patched app.asar SHA-256>",
  "executableSha256": "<actual RazerAppEngine.exe SHA-256>",
  "appliedAtUtc": "<UTC ISO timestamp after verified replacement>",
  "bladeProductIds": [563, 736]
}
```

Указанные выше идентификаторы приведены для примера; фактический маркер содержит все исключённые числовые PID из встроенного реестра. Пути в маркере не сохраняются. Интеграция OpenBlade может сверить маркер с соседним архивом, родительским исполняемым файлом, текущим процессом и встроенным реестром. Если маркер отсутствует или не совпадает, распознавание должно отключаться. Старые версии OpenBlade без такой интеграции продолжают выполнять обычные проверки конфликтов.

<a id="evidence-and-limits"></a>
## Доказательства и ограничения

- В исторической проверке Blade 16 `1532:02E0` наблюдаемые 90-байтовые и 374-байтовые отчёты не отправлялись в трассировках запуска и выхода. Короткие запросы из системного контекста сохранялись.
- Пользователь сообщил, что Pro Click V2 `1532:00D1` обнаруживалась, обычный ввод работал и запрошенные проверки настройки проходили, когда Blade отсутствовал. Это сведения от пользователя.
- Общие нативные маршруты и маршруты хоста остаются доступны. Полная изоляция, другие периферийные устройства, переход в спящий режим и возобновление работы, а также поведение оборудования в будущих сборках не проверены.

Объём проверки артефактов и тестов описан в [VALIDATION.md](VALIDATION.md). Команда `npm test` запускает проверки политики, совместимости и диагностики только на уровне исходного кода. Команда `npm run test:operations` проверяет поиск установленной версии и обратимую замену с помощью одноразовых синтетических файлов. Перед запуском `npm run test:local` задайте в `BLOCKER_PREPARATION_DIRECTORY` папку, полученную после новой подготовки; команда проверит соответствие папки текущему исходному коду патча, а затем выполнит проверки модулей с заглушками нативных зависимостей, которые не обращаются к системе. Никогда не добавляйте в коммиты сгенерированные архивы, извлечённый код поставщика или необработанные диагностические записи.

Лицензию проекта должен выбрать владелец репозитория. Компоненты Razer не включены в этот репозиторий, и репозиторий не предоставляет на них лицензию.
